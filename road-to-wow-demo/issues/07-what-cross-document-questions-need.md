# คำถามข้ามเอกสารต้องการโครงสร้างอะไรที่ top-k ให้ไม่ได้

Part of: [map.md](../map.md)

## Question

ผู้ใช้ระบุว่าคำถามข้ามเอกสารคือแหล่งของ wow — **แต่ retrieval แบบ top-k
ตอบคำถามพวกนี้ไม่ได้โดยธรรมชาติ ไม่ว่า embedding จะดีแค่ไหน**

เหตุผลเชิงโครงสร้าง: "หลักสูตรนี้ปรับปรุงกี่ครั้ง" ต้องการ **ครบทุกฉบับ** ไม่ใช่
**10 ฉบับที่ใกล้ที่สุด** — เป็นคำถามเชิงรวบยอด (aggregation) ไม่ใช่เชิงค้นหา (search)
ส่วน "มติไหนยกเลิกมติไหน" ต้องการ **ความสัมพันธ์ระหว่างเอกสาร** ซึ่งตอนนี้
ไม่ได้ถูกสกัดเก็บไว้ที่ไหนเลยในระบบ

**ตั๋วนี้ต้องตัดสินว่า คำถามกอง wow แต่ละแบบ ต้องการความสามารถอะไร และอันไหนคุ้มพอจะทำ**

### แกนที่ต้องตัดสิน

1. **จำแนกคำถามกอง wow ตามความสามารถที่มันต้องการ**:
   - *aggregation* (นับ, ไล่ไทม์ไลน์, "ทั้งหมดมีอะไรบ้าง") → ต้องการ metadata filter + การดึงแบบครบ ไม่ใช่ top-k
   - *relation* ("ยกเลิก/แก้ไข/สืบเนื่องจาก") → ต้องการกราฟความสัมพันธ์ที่ยังไม่มี
   - *comparison* ("เคยตัดสินแนวไหนมาก่อน") → ต้องการ retrieval หลายรอบ + สังเคราะห์
2. **ความสัมพันธ์ระหว่างมติจะได้มาจากไหน** — สกัดด้วย LLM ทั้ง corpus (2,853 ฉบับ,
   มี Ollama ในเครื่องอยู่แล้ว)? จาก `meeting_manifest.json`? จากการอ้างอิงในตัวข้อความ
   ("ตามมติที่ประชุมครั้งที่ N/ปี")? — วิธีสุดท้ายน่าจะถูกที่สุดและเช็คได้ด้วย regex
3. **ทำอันไหนก่อน** — ทำครบทุกความสามารถคือโปรเจกต์ใหญ่ ต้องเลือกอันที่ให้ wow ต่อแรงมากที่สุด
4. **ขอบเขต** — ความสามารถไหนที่ยอมรับว่าเดโมนี้ยังทำไม่ได้ และจะรับมือยังไงถ้าถูกถามสด

## ผลกระทบต่อคำถามตั้งต้นเรื่อง fine-tune

ถ้าใบนี้สรุปว่า wow ส่วนใหญ่มาจาก aggregation กับ relation —
**การ fine-tune embedding แทบไม่ช่วยเลยกับส่วนที่สร้าง wow** ซึ่งเป็นข้อมูลเข้าสำคัญของตั๋ว 08
